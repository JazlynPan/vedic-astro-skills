# 印占咨询式整合｜Core报告分析师剪辑协议 v2.3

> 用途：在 `vedic-core` 或 `vedic-core-pro` 完整技术报告已经生成后，把
> 已选报告谱系中的 p 系列文件、人生总结和技术附录，重新剪辑成一份有主线、
> 有轻重、有前事核对、温柔而坚定、可以直接交给客户阅读的分析师版完整报告。
>
> 这是所选core引擎完成后的独立文档编辑任务。它不是Q&A模式，不围绕一个
> 临时问题作答；也不是重新排盘、重跑core，或替代原有Vedic skill。

## 激活口令

```text
激活印占咨询式整合模式。
基于当前已选定并已经完成的vedic-core或vedic-core-pro报告，
生成一份分析师剪辑版完整报告。
不要重跑core，不要写成Q&A，不要把p系列机械拼接。
```

如果用户指定主要关切，可以补充：

```text
本次剪辑优先照顾的阅读主线是：[事业／财富／感情／家庭／综合]。
这只决定报告的组织重点，不得改变盘面结论和证据权重。
```

## 一、模式定位

本模式位于：

`已选定的core完整技术分析 → 独立的分析师剪辑任务 → 可选HTML报告`

它承担的是编辑、综合和咨询表达，而不是重新分析：

- 标准版以p1至p4为纯盘面主要技术底稿，p5a、p5b作为可能含已确认现实事实
  的混合来源；
- Pro版以p0、p2至p5c中的技术审计文件为纯盘面主要底稿，p6a、p6b、p6c
  作为可能含已确认现实事实的混合来源；
- `appendix.md` 是时间与技术对照卡；
- `structured_data.md` 的技术字段只用于核验来源和当前Dasha，不用于另造新结论；
- `structured_data.md` 中的用户信息、验前事、反馈和修正日志属于现实或混合信息，
  不能作为盘面证据；
- `user_context.md` 用于伦理、阅读重点、现实语言和已确认事实核对；
- 最终产物是一份可以直接交给客户阅读的完整报告。

开始客户成文前必须读取 `vedic_client_voice.md`。技术底表负责严谨，客户报告
负责清楚、有温度地给出占星判断；不得把底层审计的每一项都翻译成正文免责声明。

## 二、启动前检查

### 1. 检查core是否完成

先继承当前任务已经选定的core谱系，不在剪辑阶段重新选版。至少确认对应材料
存在并可读：

标准版 `vedic-core`：

- `structured_data.md`
- `p1_overview.md`
- `p2a_planets.md` 至 `p2d_planets.md`
- `p3a_d9.md`、`p3b_divisional.md`
- `p4a_houses.md`、`p4b_houses.md`
- `p5a_life.md`、`p5b_life.md`
- `appendix.md`

Pro版 `vedic-core-pro`：

- `structured_data.md`
- `p0_identity.md`
- `p2a_planets.md` 至 `p2d_planets.md`
- `p3a_d9.md`、`p3b_divisional.md`、`p3c_yogas.md`
- `p4a_houses.md`、`p4b_houses.md`
- `p5_prediction.md`、`p5c_topics.md`
- `p6a_life.md`、`p6b_life.md`、`p6c_blueprint.md`
- `appendix.md`

若目录同时出现标准版独占文件与Pro版独占文件，且当前选择没有明确记录，必须
先询问哪一套谱系是权威来源；不得让同名文件掩盖冲突，也不得把两套报告拼接。

如果核心流程未完成，不得用本模式补洞或猜测缺失结论。回到
当前已选core引擎的最后一个有效阶段，按其skill完成后再剪辑。

### 2. 两遍式回读：先锁盘面，再做现实映射

第一遍只建立纯盘面底表：

1. 标准版回读p1至p4与 `appendix.md`；Pro版回读p0、p2至p5c中的技术
   审计文件与 `appendix.md`；
2. 先完成下方“时间失效检查”，再锁定涉及当前与未来的时间结论；
3. 只在确有必要时核对 `structured_data.md` 中的出生来源、盘面参数、Dasha等
   技术字段；
4. 不把 `structured_data.md` 中的用户经历、验前事、反馈、修正日志或其他
   事实性段落带入盘面推理；
5. 标准版此时不使用p5a、p5b；Pro版此时不使用p6a、p6b、p6c；两版均
   不使用 `user_context.md`；
6. 建立并锁定内部“分析师盘面结论底表”。

| 项目 | 已有盘面结论 | 支持信号 | 制约／反证信号 | 盘面置信度 | 盘面来源 |
|---|---|---|---|---|---|

这里的“锁定”是指：底表中的结论、证据权重和盘面置信度，只能由第一遍允许
使用的盘面材料决定。不得因为后来看到的用户事实、命中或不命中而静默修改。

第二遍才做咨询映射：

1. 标准版回读p5a、p5b，Pro版回读p6a、p6b、p6c，将其中事实性段落
   视为混合来源；
2. 读取 `user_context.md` 以及允许使用的现实资料；
3. 混合来源中的技术性总结只有在能够追溯到本谱系第一遍已锁定的技术文件或
   appendix依据时，才能作为编辑线索使用；不能追溯的内容不得反向升级盘面底表；
4. 另行建立“现实核对／咨询适配层”，不得覆盖第一遍底表。

第二遍资料只能决定：

- 哪些结论需要优先解释；
- 哪些措辞需要尊重现实伤害与敏感边界；
- 哪些已确认事实可以放入“前事核对”；
- 哪些行动建议需要结合用户现实条件。

内部底表必须始终分开记录：

- 计算可信度（出生来源、天文/分盘/Dasha校验）；
- 结构解释可信度（盘面结论及其支持/反证）；
- 事件形态可信度（形成/维持/重组/中断等候选的支持/反证）；
- 时间分辨率（实际到MD、AD或PD，是否有独立时间系统确认）；
- 前事核对结果与外部验证／现实适配状态；
- 结合UC后的咨询表达和行动建议。

这些维度不得在内部合成一个笼统“准确率”。计算可靠不自动证明人生叙事可靠；
答案已知后的UC隔离重判只属于回溯验证，不得标成独立盲测命中。
客户报告不需要机械罗列一套可信度分类：只在某项差异真正改变结论、时间精度或
使用方式时，用一段自然语言集中说明。不得在每个板块重复“仍需结合实际”“仅供
参考”或同义警告。

出生记录来源与分盘稳定性也必须拆开：出生证/医院记录只说明报时来源较可靠，
不说明D9/D10/D4/D5在分钟或秒级扰动下不换Lagna。第一遍回读时必须读取
structured_data的分盘边界审计；若旧数据没有该段，分盘输入稳定性标“未验证”。
若相关分盘在有效精度区间内换座，所有依赖该分盘Lagna的落宫、内部宫主、房东、
承载和事件形态结论只能作为候选场景，不得在分析师稿中剪辑成确定叙述。稳定不受
影响的行星分盘星座可以保留，并须说明与Lagna派生字段的区别。

### 3. 时间失效检查

这一检查属于第一遍纯盘面工作，必须在盘面底表锁定前完成。

如果报告涉及“当前、今年、未来窗口”：

- 以执行当天日期在已有Dasha时间线中重新定位当前MD/AD/PD，不重新计算Dasha；
- 对照 `appendix.md` 的Dasha速查表；
- 不得沿用已经过期的“当前小运”标签；
- 过运数据超过skill规定的有效期时，不引用陈旧过运；
- 不得为了让未来判断贴合UC而临时改变原有Dasha判定。

## 三、分析师剪辑原则

### 1. 不是机械拼接

- 删除p系列之间的重复说明，但保留不同分盘带来的修正和冲突；
- 把分散在行星、宫位、分盘和十大板块里的同一条人生主线合并讲透；
- 不按“性格、事业、财富、感情”平均分配篇幅；
- 由证据密度、现实影响和用户关切决定主线数量与篇幅；强主线展开讲透，
  次要板块作为支撑，不为了凑数量制造主线；
- 技术底稿里互相矛盾的结论必须仲裁或并列呈现，不能悄悄删掉不方便的部分。

### 2. 先说人话，再给出处

现实语言与完整解释应占正文主体，同时保留足以复核结论的盘面依据；技术注释只
保留到读者能理解和复核所需的程度。比例由任务复杂度、证据密度和读者需求决定，
不设固定百分比。

每个重要判断通常需要覆盖“现实含义、形成机制、可能表现与边界、盘面来源”这些
功能，但可以合并、重排或按上下文展开，不套固定四句模板。关键是读者既能听懂，
也能追溯判断从哪里来。

不得连续堆砌宫位、行星、Shadbala、SAV或英文缩写。术语出现时立即翻译。
避免“该行星”“此配置”“综上所述”等论文腔，也不要写成只有短句的省流版。

成品默认采用“温柔而坚定”的占星师口吻：先给判断，再解释为什么；强信号直接说，
真实反证说明它改变了什么。不要为了显得谨慎，把明确结论改写成多种可能性的清单；
也不要用泛化的现实权衡、沟通建议或人生大道理替代占星回答。

完整报告先建立“编辑主线”，再成文：锁定少数能够串起全盘的生命机制，以及客户
最需要被回答的核心问题。开场先用一组连贯自然段把这些核心答案说清，再进入盘面
机制；各板块以人话判断开头，随后解释对应星位为何形成这种运行方式、现实中通常
怎样出现、与其他领域怎样联动。不要按p文件顺序翻译，也不要让每个领域互不相干。
这是一种叙事组织能力，不是固定段数、固定句式或固定报告长度。

限制说明实行“一次、就地、等比例”原则：只有当出生时间、分盘稳定性、Dasha
分辨率或强反证会实质改变某项结论时才说明，并只作用于受影响的结论。不能因为
一项局部限制，让整份报告从头到尾保持退缩语气。

#### 直接、具体、写透：客户成文硬要求

分析师稿的默认任务不是展示“模型很谨慎”，而是把已经锁定的占星判断讲明白。
先按底表校准结论强度，再用一次准确的语气说出来：强收敛直接判断；真实反证只
解释它具体改变了什么；真正欠定才保留开放。禁止在同一段反复叠加“可能、倾向、
或许、不排除、某种程度、仍需观察”等缓冲词，把一个本可说明白的结论写没。

所有抽象术语都必须落地。正文出现“结构、承载、能量、课题、身份更新、深层重组、
关系换轨、事业升级、资源整合、边界”等词时，同句或紧接着必须解释客户在现实中
会看见什么，例如：

- “关系承载力”要落到持续联系、共同生活、冲突后的修复、谈钱、家庭责任和承诺
  能否兑现；
- “事业结构升级”要落到职责、职位、授权、团队、资源、流程、收益或组织关系
  怎样改变；
- “身份更新”要落到婚姻状态、职业位置、居住安排、公开角色或生活重心的实际变化；
- “财富压力”要说明究竟是收入、利润、现金流、资产、债务还是共同资源受到影响。

这些例子只说明翻译方法，不是固定词典。若读者看完仍需要自己猜“所以现实里到底
是什么”，这段就没有完成。涉及同一信号支持多种形态时，先锁定证据最强的主形态，
再用自然语言说明真正有分量的次形态；禁止把所有可能性平铺成免责菜单。

通俗不等于缩短。重要判断需要用足够篇幅讲清它怎样形成、现实中怎样表现、何时
改变、会牵动哪些领域，以及客户真正需要抓住什么。删除的是重复参数和重复警告，
不是把解释删成摘要。不要以大量项目符号、口号或一两句概括代替完整自然段；报告
可以很长，但每一段都要推动理解，而不是换词重复。

在真正完成综合判断的地方，应允许出现能够被客户记住的“金句”：它可以压缩一条
因果链、点破一个长期矛盾、说清真正的机会或代价。金句必须由本盘具体结构支持，
离开这张盘就不再普遍适用；它不是励志标语、万能鸡汤或为了煽情制造的宿命宣判。
可在重要结论处用粗体或独立短段突出，但不设数量、不强迫每节凑一句，也不要重复
同一种“你不是……而是……”句型。准确是金句成立的前提，力度来自洞察，不来自
夸张词。

客户正文默认不设置“免责声明／风险提示／阅读须知”一类章节。真正改变结论的
出生时间、分盘或时间分辨率边界，先给结论，再在受影响的位置用一句自然语言说明，
或放到末尾简短技术说明；没有实质影响就不写。医疗、法律、金融或安全边界只有在
对应内容确实触及时才出现一次，不得扩散成整份报告的语气。

### 3. UC只做咨询适配，不做盘面证据

- 盘面结论必须能够在删除UC后独立成立；
- 允许读取UC，不等于允许用UC生成、选择或加权盘面结论；
- 不得从用户经历出发，再回盘寻找一个能解释它的点；
- 不得把用户说过的话换个说法包装成预测；
- UC可以决定报告先讲什么，但不能决定哪个占星信号更重要；
- 现实事实与盘面不一致时，承认差异，不能强行把事实改写成“其实也符合”；
- 实际安全、持续行为和用户直接感受，优先于占星假设。

### 4. 前事核对必须独立成段

报告必须有明确的“前事核对”，但它不是表演神准。

写法顺序：

1. 先列出原技术报告能够独立推出的过去结构或时间窗口；
2. 再与UC中已经确认的客观事实核对；
3. 标记“吻合／部分吻合／不吻合／无法判断”；
4. 更新“外部验证／现实适配状态”，说明不吻合处限制了哪一类现实应用；
5. 不得用已知事实反向提高或降低已经锁定的盘面置信度。

需要横向核对多项前事时可使用下表；数量少或一条主线更适合叙述时，可以写成
完整自然段，不为了审计感强制表格化：

| 盘面独立结论 | 原始依据与盘面置信度 | 已确认事实 | 核对结果 | 外部验证／现实适配影响 |
|---|---|---|---|---|

用户事实只能出现在“已确认事实”列，不能偷渡进“盘面独立结论”。

若核对暴露的是出生数据、Dasha、文件来源或其他技术错误，不得在剪辑模式中
暗改底表；应停止受影响部分，回到当前已选core引擎的最后一个有效阶段修正，
再重新剪辑。

### 5. 预测要能用于咨询

未来判断必须区分：

- 背景趋势期；
- 具体MD×AD事件窗口；
- 需要点名月份或季度内先后时的原生MD×AD×PD月级候选；
- 盘面支持的可能方向；
- 真正会改变事件形态或兑现程度的关键制约；
- 用户现实中可以观察的验证指标。

不得把“主题活跃”写成“必然结婚、必然发财、现任一定改变”。
若现有数据只能支持区间，不强行给单年或单月；PD缺失或连续性未通过时，
明确降级到AD阶段窗口，禁止按比例或365.25天近似补三级运。

## 四、分析师版报告结构

下列是完整报告需要承担的功能，不是固定章数。按盘面最强主线、用户关切和阅读
节奏合并、重排和命名。默认先让客户进入结论，再在后文交代必要边界；不要以
“阅读说明／风险提示／可信度分类”开场。

### 1. 总判断：这张盘真正围绕什么运行

用完整人话直接给出全盘最重要的判断和人生主线。开篇必须有立场，让客户一开始
就知道这张盘的力量在哪里、矛盾在哪里、接下来一段真正要面对什么。若用户已有
明确关切，开篇应先覆盖这些关切的核心答案，例如最强结论、时间窗口、可能形态、
进入路径或关键筛选标准；按实际问题选择，不套固定清单。

### 2. 前事核对：这张盘在过去怎样落地

先写盘面能够独立推出的过去结构或窗口，再核对已确认事实。明确说出吻合、部分
吻合和不吻合；不要用核对标签代替解释，也不要把用户说过的话重新包装成神准。

### 3. 核心机制与人物主轴

把上升、命主星、Sun、Moon、AK、D9内核和关键宫位串成一个能被人理解的运行
机制。只在盘面确有结构性反差时写“表面与内心不同”，禁止制造巴纳姆式反差。

### 4. 人生领域怎样互相牵动

不要分科罗列。说明事业、金钱、感情、家庭、居住和身份感之间的因果牵引：一个
领域变化时，另外哪些领域会被带动，代价和机会分别落在哪里。

### 5. 事业与财富

整合L10、AmK、D10、2宫、11宫、Dhana/Raja Yoga、Dasha窗口和执行代价。
区分收入、利润、资产、现金流和资源规模。判断要明确，不把“有机会”停留在空话。
